# 个性化旅游路线定制平台 - 项目说明文档

## 一、系统概述

本系统是基于开题方案「标签建模 + 推荐排序 + 路径规划 + 反馈闭环 + AI 陪伴」理念构建的个性化旅游路线定制原型平台，实现了从用户偏好采集、景点多标签匹配、加权推荐排序、多日行程生成到行中 AI 助手陪伴的完整业务闭环。系统采用 **HTML/CSS/原生 JavaScript + Node.js Express + PostgreSQL** 前后端分离架构，面向自由行用户，提供旅行画像录入、景点智能推荐、行程规划、行中动态辅助与用户认证等核心功能。

**项目定位：** 面向自由行用户的个性化旅游路线规划与动态行程调整平台

**核心目标：** 整合多源旅游信息，为不同偏好用户生成可执行、可调整、可反馈优化的出游方案

**适用场景：** 城市一日游、周末短途、跨城自由行、亲子游、特种兵游与慢旅行

**作者：** 叶蓓莉、潘仁恺、曹天玺、丁露盈

### 技术栈

| 层级    | 技术选型                         |
|-------|------------------------------|
| 前端页面  | HTML5 + CSS3 + 原生 JavaScript |
| 前端存储  | localStorage（用户画像、行程状态持久化）   |
| 后端框架  | Node.js + Express 4.x        |
| 数据库   | PostgreSQL 12+               |
| 数据库驱动 | node-postgres (pg)           |
| 用户认证  | SHA-256 密码哈希 + 内存 Token 存储   |
| 跨域支持  | cors 中间件                     |

## 二、核心技术详解

### 2.1 景点多标签体系 —— 结构化 POI 属性建模

#### 2.1.1 标签体系概念

与传统按「景区 / 博物馆 / 商圈」进行单一分类不同，本项目采用**多维标签方法**：同一地点可同时拥有多个属性标签，并附带评分、适宜人群、建议时长等结构化字段，使景点既能被精确检索，也能参与个性化匹配计算。

#### 2.1.2 标签在系统中的体现

本系统通过 PostgreSQL 数据表严格对齐开题文档中的标签框架，实现概念到数据库字段的映射：

**核心实体 → 数据表映射：**

| 开题概念    | 系统数据表               | 职责                      |
|---------|---------------------|-------------------------|
| 景点 POI  | `attractions`       | 存储景点名称、描述、位置、评分、价格等     |
| 预设路线    | `routes`            | 存储热门路线模板（出发地、目的地、天数、偏好） |
| 路线-景点关联 | `route_attractions` | 存储路线内景点按天排序关系           |
| 用户账户    | `users`             | 存储注册用户信息                |

**标签维度 → 字段映射：**

| 标签维度（开题） | 数据库字段                                | 数据类型         | 语义含义                           |
|----------|--------------------------------------|--------------|--------------------------------|
| 主题属性     | `type`                               | VARCHAR      | 自然风光 / 人文历史 / 美食 / 休闲 / 探险等    |
| 复合标签     | `tags`                               | TEXT         | 逗号分隔多标签，如 `nature,scenic,lake` |
| 体验属性     | `recommended_duration`               | INTEGER      | 建议游览时长（分钟）                     |
| 消费属性     | `price`                              | DECIMAL      | 门票价格（0 表示免费）                   |
| 时段属性     | `open_time` / `best_visit_time`      | VARCHAR      | 开放时间与最佳游览时段                    |
| 人群属性     | `suitable_for_family/elderly/couple` | BOOLEAN      | 是否适合家庭 / 长者 / 情侣               |
| 质量评分     | `rating`                             | DECIMAL(2,1) | 景点综合评分（默认 4.0）                 |

**景点类型枚举（`type` 字段）：**

```
nature      → 自然风光
culture     → 人文历史
food        → 美食探索
relax       → 休闲度假
adventure   → 户外探险
shopping    → 购物娱乐
scenic      → 拍照打卡
entertainment → 娱乐体验
nightlife   → 夜生活
```

#### 2.1.3 示例数据

**实现文件：** `backend/init.sql`

系统预置 5 条经典路线模板与 23 个全国代表性景点，覆盖云南、川西、江南、北京、厦门等目的地，每条景点记录均包含完整标签、评分、价格、适宜人群与开放时间字段，可直接用于推荐与行程演示。

### 2.2 用户画像与个性化推荐 —— 加权匹配评分引擎

#### 2.2.1 用户画像概念

用户画像是系统理解旅行者个性化需求的结构化表达。首次进入首页时，用户填写出发城市、目的地、出行天数、游玩强度、兴趣标签（多选）与同行人类型，系统将其持久化存储，作为后续推荐与行程生成的输入条件。

#### 2.2.2 画像数据结构

**前端存储键：** `travel_user_profile`（localStorage）

**画像字段：**

```
{
  departure: "北京",           // 出发城市
  destination: "杭州",         // 目的地
  days: "4-7",                 // 出行天数区间
  intensity: "moderate",       // 游玩强度
  interests: ["nature","culture","food"],  // 兴趣标签（多选）
  companion: "couple",         // 同行人类型
  updatedAt: "ISO8601时间戳"
}
```

**兴趣标签选项（8 维）：**

| 值           | 含义   |
|-------------|------|
| `photo`     | 拍照打卡 |
| `food`      | 美食探索 |
| `culture`   | 人文历史 |
| `nature`    | 自然风光 |
| `shopping`  | 购物血拼 |
| `adventure` | 户外探险 |
| `relax`     | 休闲度假 |
| `nightlife` | 夜生活  |

#### 2.2.3 推荐评分算法

**前端实现文件：** `scripts/recommend.js` → `calculateMatchScore()`

**后端实现文件：** `backend/server.js` → `GET /api/recommendations`

系统采用**加权评分**方式计算景点与用户画像的匹配度（0–100 分）：

```
基础分：50 分

加分规则：
  ├── 兴趣标签匹配：每命中一个兴趣 +15 分
  │     （匹配 type 字段或 tags 字段中的关键词）
  ├── 游玩强度适配：
  │     ├── relaxed（休闲）+ 时长 ≤ 90 分钟 → +10 分
  │     └── intensive（紧凑）+ 时长 ≥ 180 分钟 → +10 分
  ├── 同行人适配：
  │     ├── family → suitable_for_family = true → +10 分
  │     ├── elderly → suitable_for_elderly = true → +10 分
  │     └── couple → suitable_for_couple = true → +10 分
  └── 评分加成：(rating - 3) × 5

最终分数：clamp(0, 100)
```

**推荐理由生成：** 系统同步输出可解释的匹配理由（如「符合自然风光偏好」「适合情侣出游」），对应开题方案中 AI 解释推荐原因的设计目标。

#### 2.2.4 推荐在业务链路中的位置

```
用户填写画像 → 保存 localStorage
    ↓
跳转推荐页 → 调用 GET /api/attractions 或 /api/recommendations
    ↓
calculateMatchScore() 计算匹配度
    ↓
按 matchScore 降序排列 → 展示景点卡片（含匹配度百分比）
    ↓
用户勾选景点 → 确认生成行程
```

### 2.3 路线规划与行程生成 —— 多日时间轴编排

#### 2.3.1 技术定位

开题方案提出接入腾讯地图 API 进行路径优化与动态重规划。当前原型以前端**规则化行程编排**实现可执行路线生成，结合景点建议时长与模拟交通时间，输出按天分组的时间轴行程，为后续接入真实地图 API 预留接口。

#### 2.3.2 行程生成逻辑

**实现文件：** `scripts/itinerary.js` → `generateItineraryData()`

```
输入：用户选中的景点列表 + 用户画像（天数区间）
    ↓
天数映射：
  ├── 1-3 天 → 2 天行程
  ├── 4-7 天 → 5 天行程
  ├── 8-15 天 → 7 天行程
  └── 15+ 天 → 10 天行程
    ↓
景点均分到各天 → generateDaySchedule() 生成每日时间轴
    ↓
输出：{ totalDays, days: [{ day, date, attractions: [...] }] }
```

**每日时间槽分配：**

| 序号 | 开始时间  | 结束时间  |
|----|-------|-------|
| 1  | 09:00 | 10:30 |
| 2  | 11:00 | 12:30 |
| 3  | 14:00 | 15:30 |
| 4  | 16:00 | 17:30 |
| 5  | 19:00 | 20:30 |

#### 2.3.3 交通时间估算

**实现文件：** `scripts/itinerary.js` → `estimateTransportTime()` / `getTransportMethod()`

相邻景点之间自动插入交通节点：

```
估算时间 = 15 分钟（基础）+ 随机 0–20 分钟

交通方式判定：
  ├── ≤ 10 分钟 → 🚶 步行
  ├── ≤ 20 分钟 → 🚌 公交
  ├── ≤ 30 分钟 → 🚇 地铁
  └── > 30 分钟 → 🚕 打车
```

#### 2.3.4 行程统计

系统自动计算并展示：

| 统计项   | 计算方式                   |
|-------|------------------------|
| 总天数   | 根据天数区间映射               |
| 景点数量  | 用户选中景点总数               |
| 总游玩时长 | Σ recommended_duration |
| 预估费用  | Σ price                |

### 2.4 AI 行中助手 —— 关键词驱动的陪伴式服务

#### 2.4.1 技术定位

开题方案提出 AI 模块承担「地陪式服务」角色。当前原型通过**关键词匹配 + 规则模板**实现轻量级行中助手，覆盖时间提醒、美食推荐、注意事项、行程调整等核心场景，后续可替换为大语言模型 API。

#### 2.4.2 助手架构

**实现文件：** `scripts/trip.js`

**行中状态机：**

```
pending（未开始）
    ↓ 标记已到达
arrived（已到达）
    ↓ 开始游览
visiting（游览中）→ 启动游览计时器 + 闭园时间提醒
    ↓ 结束游览
completed（已完成）
    ↓ 前往下一景点
pending（下一景点）
```

**AI 对话能力（关键词触发）：**

| 用户输入关键词 | 助手响应                     |
|---------|--------------------------|
| 美食 / 吃  | 推荐当前景点附近美食（模拟数据）         |
| 注意 / 事项 | 输出开放时间、门票、建议时长与温馨提示      |
| 调整 / 行程 | 打开行程调整模态框（跳过 / 延时 / 重规划） |
| 其他      | 引导用户使用快捷功能菜单             |

**行中辅助功能：**

| 功能   | 实现方式               |
|------|--------------------|
| 行程计时 | 从「开始行程」起累计总时长      |
| 游览计时 | 单景点游览实时计时          |
| 进度追踪 | 已完成 / 总景点数进度条      |
| 天气展示 | 模拟天气数据随机生成         |
| 导航信息 | 模拟距离与预计到达时间        |
| 闭园提醒 | 16:00 后自动推送时间风险警告  |
| 行程调整 | 跳过景点 / 延长游览 / 重新规划 |

#### 2.4.3 状态持久化

行中数据存储于 `travel_current_trip`（localStorage），包含行程结构、当前景点索引、开始时间与游览状态，页面刷新后可恢复进行中的行程。

## 三、核心业务执行链路

当用户在首页提交旅行画像并点击「生成路线建议」时，系统完整执行以下 8 步处理流程：

```
Step 1: 首页表单提交 → 保存用户画像到 localStorage
         → 构建 URL 参数跳转 recommend.html
    ↓
Step 2: 推荐页加载 → 读取画像参数
         → 调用 GET /api/attractions?city=&type=
    ↓
Step 3: 前端 calculateMatchScore() 计算每个景点匹配度
         → 生成 matchScore + matchReasons
         → 默认选中 Top 8 景点
    ↓
Step 4: 用户浏览推荐列表 → 可增删景点
         → 实时预览多日行程时间轴
    ↓
Step 5: 确认生成行程 → 保存到 localStorage
         （travel_selected_attractions + travel_route_params）
         → 跳转 itinerary.html
    ↓
Step 6: 行程详情页 → generateItineraryData() 生成完整日程
         → 渲染统计卡片 / 地图标记 / 分日时间轴
         → 插入景点间交通节点
    ↓
Step 7: 点击「开始行程」→ 保存行中状态到 localStorage
         → 跳转 trip.html 进入行中助手模式
    ↓
Step 8: 行中助手 → 景点状态机驱动游览流程
         → AI 对话 / 时间提醒 / 行程调整
         → 完成后输出行程总结
```

**「推荐 + 规划 + 陪伴」三重机制说明：**

- **加权推荐（第一层）：** 基于用户画像的多维标签匹配，提供可解释的推荐理由与匹配度百分比
- **规则化规划（第二层）：** 按天数均分景点、分配时间槽、估算交通，生成可执行的日程表
- **AI 助手（第三层）：** 行中实时陪伴，提供提醒、问答与动态调整能力

### 环境要求

- Node.js 14.0+
- PostgreSQL 12.0+
- 现代浏览器（Chrome / Edge / Firefox）

### 启动步骤

```bash
# 1. 创建并初始化数据库
psql -U postgres
CREATE DATABASE traveltool;
\q
psql -U postgres -d traveltool -f backend/init.sql

# 2. 配置后端环境变量
# 编辑 backend/.env：
# DB_HOST=localhost
# DB_PORT=5432
# DB_NAME=traveltool
# DB_USER=postgres
# DB_PASSWORD=你的密码
# PORT=3000

# 3. 启动后端
cd backend
npm install
npm run dev          # 开发模式（热重载）
# 或 npm start       # 生产模式

# 4. 启动前端（推荐本地服务器）
cd ..
python -m http.server 8080
# 访问 http://localhost:8080/pages/home.html
```

### 验证服务

- 后端健康检查：http://localhost:3000/api/health
- 前端首页：http://localhost:8080/pages/home.html

### 使用流程

1. 在首页填写出发地、目的地、天数、强度、兴趣标签与同行人类型
2. 点击「生成路线建议」进入推荐页，查看匹配度排序的景点列表
3. 勾选/取消景点，预览多日行程时间轴
4. 点击「确认生成行程」查看完整行程详情
5. 点击「开始行程」进入行中助手，体验 AI 对话与游览状态管理
6. （可选）注册登录账号，在个人中心查看账户信息

## 附录：数据库表结构概览

### routes（路线表）

| 字段               | 类型           | 说明          |
|------------------|--------------|-------------|
| id               | SERIAL       | 主键          |
| title            | VARCHAR(255) | 路线标题        |
| description      | TEXT         | 路线描述        |
| departure_city   | VARCHAR(100) | 出发城市        |
| destination_city | VARCHAR(100) | 目的地城市       |
| days             | INTEGER      | 天数          |
| budget_level     | VARCHAR(50)  | 预算等级（低/中/高） |
| preference       | VARCHAR(100) | 偏好标签（逗号分隔）  |
| image_url        | VARCHAR(500) | 封面图 URL     |

### attractions（景点表）

| 字段                                 | 类型            | 说明         |
|------------------------------------|---------------|------------|
| id                                 | SERIAL        | 主键         |
| name                               | VARCHAR(255)  | 景点名称       |
| type                               | VARCHAR(100)  | 主题类型       |
| tags                               | TEXT          | 复合标签       |
| city                               | VARCHAR(100)  | 所在城市       |
| rating                             | DECIMAL(2,1)  | 评分         |
| price                              | DECIMAL(10,2) | 门票价格       |
| recommended_duration               | INTEGER       | 建议游览时长（分钟） |
| suitable_for_family/elderly/couple | BOOLEAN       | 适宜人群       |
| open_time / best_visit_time        | VARCHAR(100)  | 开放与最佳时段    |

### users（用户表）

| 字段            | 类型           | 说明           |
|---------------|--------------|--------------|
| id            | SERIAL       | 主键           |
| username      | VARCHAR(50)  | 用户名（唯一）      |
| email         | VARCHAR(100) | 邮箱（唯一）       |
| password_hash | VARCHAR(255) | SHA-256 密码哈希 |
| nickname      | VARCHAR(50)  | 昵称           |
| phone         | VARCHAR(20)  | 手机号          |
